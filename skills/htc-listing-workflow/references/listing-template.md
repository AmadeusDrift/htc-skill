# 上架填表与精确下拉约束

## 字段与样板

1. 使用 spreadsheets 技能。先读取所有工作表、有效字段表头和机器属性行、样板组、必填提示、数据验证、命名范围、隐藏选项表、条件格式和公式。Amazon 反馈可能在前面插入状态列，禁止写死 SKU=A、标题=G 或 AA 后所有列等绝对位置。
2. 以 `contribution_sku`、`parentage_level`、`child_parent_sku_relationship`、`item_name`、`main_product_image_locator`、`other_product_image_locator` 等机器属性辨认字段；无法唯一识别则询问。
3. 找到完整父体/子体组，复制相同角色的已确认常量、格式、数据验证适用关系和公式相对引用。父体、左/中/右各自继承，不能把父行的空值覆盖售卖子体，也不能把子体价格、重量灌入父体。
4. 更新 SKU、父 SKU、最终标题和正确云图链接；款式标识按人工样板的实际选项/合法值继承，不擅自改成英文位置名。缺云图时留明确待补项，不用本地路径假装云图。

## 下拉：实际合法值是硬约束

检查每个待填写、复制或扩展到的 list 类型数据验证，解析来源可能是：字面量列表、隐藏表单元格范围、带空格表名的跨表范围、工作簿/工作表命名范围、动态公式或联动列表。静态命名范围可递归解析；`INDIRECT`、`OFFSET`、公式生成、依赖其他字段的下拉不得凭记忆猜测。

`scripts/workbook_rules.py` 提供只读解析与精确匹配。无法解析时，须以可用的 Excel/文档会话读取当行真实选项，或要求用户确认合法值；仍然无法确定就标记 unresolved，不能以“有数据验证对象”冒充验证成功。

不能把 `checked=0` 当成校验通过；检查是否缺少规则、验证范围未覆盖、目标全空或过滤坐标不匹配。扩展 `x14` 数据验证未能解析时也要记 unresolved。空值的必填性另按父子角色判断，不能因为脚本跳过空白而称必填已齐。

字符串必须逐字符相等：`COLOR ≠ color`，`New ≠ new`，`A B ≠ A  B`。保留选项本身的大小写、空格、标点和单位。不能先 lower/strip 再当成合法。Excel引用公式外层的语法空白可解析，但不清洗实际列表值。

样板不豁免校验：如样板写了 `color`、真实选项只有 `COLOR`，提出冲突，询问是否按该合法选项修正；不得继续复制或宣称可以上传。若用户明确要求的选择不在列表中，列出选项让用户选，不因用户给了值就静默绕过。

## 必填项

结合字段定义/说明、模板有效验证条件和父子角色识别必填，不能只凭列色或空值判断所有列都必填。若代码无法确定条件，记录 unknown 并询问业务条件。人工提供的真实商品信息优先继承，不从图像推测精确尺寸、重量、认证、产地或授权。

无完整样板时返回原有完整中文表单，保留已填内容，只在“上架样板位置”或“其他商品信息”旁标注需补的必填资料与可选值，不要求用户填写内部 `product_info` JSON。没有上架表则不要求这些上架业务字段，不阻止正常图片模式。

## 原生工作簿保存与验证

使用 artifact-tool 生成/编辑值；必要时把该工具生成的已验证值局部合并回原 OOXML 部件，保留 `.xlsm` 的内容类型、VBA、名称、数据验证、隐藏表和原有备注。不用 openpyxl/pandas 重新保存或创建业务工作簿；openpyxl可只读解析、验证。

保存后重新打开真实输出文件：逐行核对字段，逐项验证 dropdown membership、必要字段、连续序号、父子关系、云图配对与无公式错误。复核未修改原生 ZIP 部件字节一致、模板格式和数据验证仍存在。用临时预览解决渲染器兼容问题时，不把仅为预览调整的列宽/样式写入交付表。

输出上架修正版到新文件。历史 Feed Processing Summary 和状态列是历史反馈，不改成新“成功”；在校验记录中另列“文件检查已处理/平台待复传”。不自动向 Amazon 提交。
