# 一张合并的中文输入表单

## 对外默认模板

普通单品和父子体始终提供同一张表，不另拆父子体表单。括号标记的四项只在有父子体时填写，没有就留空。不要向使用者要求 JSON、英文键名、schema_version 或 null。

```text
使用 htc上架工作流

【HTC上架工作流输入】
图片目录：
本批起始SKU：
商品模式：普通单品
标题模板：

云图链接表：
上架表：
上架样板位置：自动识别
其他商品信息：

分组方式（父子体时填）：
父图（父子体时填）：
子图及SKU后缀（父子体时填）：
售卖方式（父子体时填）：

输出位置：图片目录同级新文件夹
特殊要求：
```

## 填写与缺项判定

- 图片目录：本批原图绝对路径，Windows路径可直接写反斜杠，无需 JSON 转义。
- 本批起始SKU：完整首号，例如 `SKU001`，本批从该号开始，不是已使用末号。
- 商品模式：普通单品 / 父子体。普通单品的四个父子字段留空有效；父子体需要明确分组、父图、子图及后缀、售卖方式。若写了普通单品却又填写父子信息，只标记商品模式冲突，不擅自改掉原值。
- 标题模板：英文具体模板，使用 `{关键词}` 插入图案关键词。可以写“沿用该产品已确认模板”，但仅在当前可读资料或聊天确有具体模板时解析；找不到时标记该字段需确认，不另猜历史产品模板。
- 云图链接表、上架表：没有就留空，也接受“未提供/无”，不因此阻止图片及对照表输出。
- 上架样板位置：无上架表时忽略；有表时可写“模板工作表第7～10行”，或保留自动识别。表内无完整样板则只读识别需要哪些业务资料。
- 其他商品信息：填写需要补充的形状、重量、单位、价格等；已有人工样板时按样板继承，不要求重复抄写。不要求普通图片模式提供上架专用字段。
- 分组方式：如“每个编号文件夹一组”。父图如 `90x40.png`；子图及后缀如“左.png对应-A，中.png对应-B，右.png对应-C”；售卖方式如“子体单幅售卖，父体仅展示关联”。这些只是写法举例，不自动填进用户的空表。
- 输出位置留空时使用同级新结果目录；特殊要求没有就留空。默认不生成 ZIP，不要求运营配置表。

## 缺资料时的回复

先用一句中文说明“以下标注处需要补充或确认，其余已填内容已保留”，紧接**原有完整中文表单**。规则：

1. 保留用户全部已填值、大小写、原有次序、额外附注及其他商品信息。不得清空未受影响字段，不能重写成另一份示例。
2. 空的必要字段，在该行加 `【待补：具体要求】`。例如 `标题模板：【待补：请提供含{关键词}的具体英文模板】`。
3. 已填但冲突或无法验证的字段，原值不变，末尾加 `【需确认：具体问题】`。例如 `商品模式：普通单品【需确认：已填写父子分组信息，请确认模式】`。
4. 可选空字段不标待补，普通单品不要求补父子字段。无上架表不要求补样板、形状或重量。
5. 若缺少整行必要字段，追加对应中文字段并标记，不删除其他行。没有结构化输入时，提供上面的一张合并表，可回填当前聊天明确的值，但需用户提交确认后的表单，不能回填后自行开工。
6. 已完整提交后，后续明确更正可更新同一表单，不要求每条问答重填。重新返回仍用中文；不能用英文错误列表替代问题说明。
7. `【待补：…】`、`【需确认：…】` 是系统检查注释，不是商品数据。补填后即使保留这些注释，内部解析也须排除；若问题仍在，只更新同一标记，不反复叠加。独立“备注”原样保留但不得拼入标题、SKU或路径；只有其他商品信息和特殊要求可以承接其明确的续行。

`scripts/chinese_input.py --form 输入.txt [--check-paths] [--output 内部检查.json]` 实现常见表单检查与原文保留回复。自然语言附注、未知样板必填项等仍由模型结合当前资料判断并按上述规则回填；脚本通过不代表业务资料已齐。

内部仍使用 `htc-listing-v1` schema；仅供脚本调用，默认不对用户展示。`input_gate.py --request` 保留程序调用兼容性。内部 `template_rows` 是含工作表和起止行的对象；`product_info` 保存本批已确认资料。中文路径、首SKU和选项值不得在内部转换时改写。
