# htc上架工作流

把图片识别、SKU、文案扫描修订、图片对照表和可选上架填表连成一次任务。默认无运营配置表、无 ZIP，保留所有原文件。此技能独立于 `run-pod-first-workflow`，不改动或调用其旧计数器规则。

## 入口硬门槛：先检查结构化输入

**任何批处理、历史批次修正都必须先有本技能的结构化输入。** 默认且唯一对外提供的是 [合并中文输入表单](references/structured-input.md)，普通单品和父子体共用一张表；父子体相关字段没有就留空，不拆出第二张表，不要求运营填写 JSON、英文键名、schema_version 或 null。

- 没有结构化输入：回复“请按下面的中文表单填写后再开始”，提供完整合并中文表单，可回填当前聊天明确提供的值；**不能把回填视为用户已提交表单，不开始生成、改名、填表或安装依赖**。即使已有文件、SKU 或用户说“直接做”，也要提示中文结构化提交；只有用户明确撤销该门槛时才遵从新指令。
- 有表单但必要资料缺失、占位符未替换、路径不可用或资料冲突：返回使用者的完整中文表单，**保留所有已填写的内容、原有次序和附注，只在对应问题字段旁加 `【待补：具体要求】` 或 `【需确认：冲突说明】`**。不把整张表重置成空白，不重复询问已提供的信息，不返回 JSON。可只读盘点、读取样板与选项来明确缺项，不进行生产写入。
- 云图链接表、上架表等可选字段留空或填“未提供/无”均有效。普通单品的父子体字段留空有效，不要求填写“不适用”。输出位置留空采用同级新结果目录。缺云图时不得伪造链接或擅自上传图片。
- 有上架表但无完整样板：先读取必填、联动及下拉规则，再把需补的业务信息标在原表的“其他商品信息”或“上架样板位置”旁，保留价格/重量等已经填写的内容。非必填空字段无须补成虚构事实。
- 通过后只回显商品模式、首 SKU、图片分组、输出位置、是否填表，信息明确则直接执行，不重复要求确认。

可用 `scripts/chinese_input.py --form 输入.txt` 检查中文表单，`--check-paths` 检查本地路径。内部转换到 `htc-listing-v1` 后调用 `input_gate.py`；这是内部实现，不要求用户接触。既有 JSON 输入保持兼容，但缺项回复仍使用中文表单。脚本仅检查格式/路径，不能替代样板完整性和业务必填审查。默认值只来自本技能，必要业务资料不可自填。

## 内置默认值

| 项目 | 默认规则 |
|---|---|
| 本批起号 | 用户填写的完整 `start_sku` **就是首号**；SKU001 → SKU001、SKU002；不是 last+1 |
| 图案 ID | 与各自 SKU 完全一致；重跑沿用原批次映射，不重占号 |
| 关键词 | 英文、逐图识别、批次内唯一；文件名主体最多15字符，空格计数并保留 |
| 标题 | 英文、按用户明确的 `{关键词}` 模板生成；默认100字符上限；不能臆定产品模板 |
| 图片 | 原扩展名、原始字节，不重压缩、不改画面；两套命名图片 |
| 保存 | 同级新结果目录或指定输出目录；已有结果生成新版本，不覆盖 |
| ZIP / 配置表 | 默认均不生成、不索要 |

仅解析父 SKU 末尾连续数字，保留前缀和补零宽度。越过位数自然扩展，不回绕。没有数字尾号或把子 SKU 当起号等歧义须询问。发现已有 SKU 碰撞须让用户指定续号或修正模式，不自行跳号。

## 执行

1. **建清单**：先只读盘点原图、尺寸、格式、目录深度和云图链接；判断独立原图与轮播素材。按用户分组建立源路径、源 SHA256、父子角色、原目录号映射。不能只按文件夹数字猜画面配对；有冲突先回结构化输入。
2. **编号与父子体**：普通单品一图一 SKU；父子模式按 `grouping` 的父图及子图/后缀创建完整组。只有父体消耗主序号；子体保存明确 `parent_sku`、位置与售卖方式。三联原图可为父展示图、左/中/右单幅售卖，但不是所有产品的默认。
3. **逐图文案**：检查每张原图；生成准确、唯一英文命名关键词、详细图案关键词和模板标题。读取 [扫描修订](references/screening.md)，用 `scripts/scan_text.py` 扫描**完整标题**，包括关键词与固定模板的接缝；有填表时同查描述、五点、搜索词。真实品牌/IP图像问题不能靠改词“通过”。
4. **修订复扫**：普通词误识别可保持图意换写；先保护商品事实和固定模板，最多3轮。仍有重要冲突就标记待复核，询问并列明位置，不无限改词。最终文案稳定后，才统一生成文件名、映射表和上架表，避免三者不一致。
5. **输出**：用 spreadsheets 技能及 artifact-tool 创建 `01_图片对照表.xlsx`（含摘要、图案清单、文案检查/修订记录），复制 `02_关键词命名图片/`、`03_SKU命名图片/`。父子模式两套均保留组目录。上架表若明确未提供，正常完成这三项。
6. **可选填表**：有上架表必读 [上架模板规则](references/listing-template.md)。识别字段属性标识和完整样板组，逐角色复制，保留父体非售卖字段空值，补入最终 SKU、父 SKU、标题、对应云图链接。`scripts/workbook_rules.py` 只读解析/校验，不能用它重存工作簿。
7. **交付验证**：检查输出数量、唯一性、首号及连续性、父子归属、文件名/标题限制、两套图片逐张 SHA256、云图链接对应、Excel公式及缓存值、必填项、数据验证和保存后的真实下拉值。报告通过项和未解决项；有未解决必填/下拉/重要文案问题，不称“可直接上传”。

对照表至少包含：组号、父子类型、位置、售卖方式、父SKU、图案ID、SKU、原路径、原目录号、命名关键词、详细关键词、标题、标题长度、两套文件名/相对路径、源SHA256、云图链接、审核状态。摘要记录首末父SKU、下一建议首号和词库快照哈希。

## 必须保持的边界

- **有人工样板先继承；有下拉必须精确取值。** `COLOR` 不等于 `color`；不对选项 trim、翻译、改大小写。样板与规则冲突也要报告，不能批量复制错误或静默改正业务选择。
- 形状、尺寸、重量、单位、价格来自本批已确认资料；无样板时不把其他商品的 `0.1 Pounds` 等值当成默认。
- `.xlsm` 保留原内容类型、工作表、隐藏表、命名范围、数据验证、宏及其他原生部件；使用局部 XML 合并保全原件，不能导出 `.xlsx` 后只改扩展名。
- 上传反馈修正只改已定位字段，保留旧反馈；`100521` 等审核状态和 `13013/8007` 等平台结果要复传核实，不能伪造成功状态或自动提交上架。
- 本地词库快照是初筛依据；输出“未命中当前规则”，不是“无侵权保证”。更新词库参考 [词库来源](references/dictionary-source.md)，默认不写 Cloudflare 数据库。

## 辅助工具

使用当前环境绑定的 Python。`chinese_input.py` 处理合并中文表单和保留原内容的缺项回复；`input_gate.py` 是内部输入/序号检查；`scan_text.py` 是文案扫描；`workbook_rules.py` 是只读选项解析。`tests/` 是离线回归测试，不属于给运营的批次输出。不要为使用本技能另建配置表或复制整个商标库到每个结果目录。
