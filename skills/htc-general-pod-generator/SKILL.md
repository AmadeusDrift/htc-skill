# HTC 通用 POD 生成

根据真实产品与印花制作商品图文、可替换印花的 PSD 母版及多款图案输出。产品形态、印制工艺、图片数量、画面内容和构图均按用户要求、适用平台及已确认事实适配；不要套用水晶标、特定产品或固定七图规则。使用用户指定的专用 skill 时遵循其产品规则。

## 识别任务与资料

- 先判断是新产品、已有批准母版换图、局部修改，还是只组合已有图片。已有成品和批准版不因本 skill 自动返工。
- 读取实物、尺寸、图案、供应商资料和用户指定参考，区分产品事实、视觉参考与设计素材。记录产品形态、真实用途、材质、可印位置、图案数量、颜色/规格及限制；缺失事实标注待确认，不猜材质、性能、尺寸、工艺或配件。仅在缺项阻止当前工作时询问，其余工作继续。
- 明确目标平台、语言、交付范围、SKU 与变体关系；平台要求影响输出时核实当前适用规则。用户有具体要求时优先执行。用户未指定时按产品、渠道和信息需要提出合适图数与内容，不把示例当硬性规格。
- 区分满版、透明独立图案与已有设计留白；保留原图和来源。仅有参考图不代表有提取或商用授权。
- 产品有多种颜色时先整理「印花 × 产品颜色」实际可售对应表及主配色；每个颜色展示其对应印花，不凭空增加颜色、组合或图案。

## 规划产品图与文案

先理解买家、购买理由和实际使用场景，按信息增量规划每张图：图位目的、真实产品、场景/镜头、必要文字、依据、可印区域及是否随 SKU 换图。主图、功能、细节、尺寸、场景、比例或其他图位按需要组合；不强制手持、三维厚度、特定卖点、颜色组合或固定版式。禁止虚构产品特征、额外印面或效果；同套避免重复。

### 全场景与复合型画面

新产品的完整轮播默认**每张都是场景图**，不把纯白背景、孤立产品抠图、纯色背景或只有装饰色块的画面当作场景。主图、卖点、功能、细节、尺寸和手持图也要放在与该产品用途和真实形态匹配的具体环境中，同时清楚完成各自的信息任务。将使用动作、产品外观、卖点/结构细节、必要短文案等按图位需要融合在同一场景内，形成有购买理由的复合型画面；细节可以通过合理的局部放大或信息区呈现，尺寸引线必须可读、指向正确边界，不因追求场景而牺牲真实性和辨识度。

完整一套事先设计**至少三个明显不同的场景**：改变真实地点、使用情境或产品摆放方式，不能靠同一背景换道具、裁切或加字冒充新场景。逐图改变画面构图与镜头关系，并拉开色调和光线；避免重复背景、同样的产品位置和同一色调。色调差异以适合产品、品牌和真实材质为前提，保持整套字体与视觉品质协调，不把产品本体或印花改成不同颜色。根据产品选择合适的差异，例如书房桌面、明亮卧室、暖色客厅仅为示例，不强套所有产品。

制作前为每张图列出场景地点/使用方式、主要色调与光线、镜头/产品位置、信息任务和印花实例，核查至少三个场景且没有重复构图或色调，再逐张生成。图片数量或用户指定范围不足以容纳三个场景时，按实际图数尽量区分，不虚构额外交付；仅修改、换印花或用户已批准的母版应保持对应画面，不因新规则自动重做。平台明确要求白底或用户明确指定白底时遵循该要求并注明适用范围。

### 多颜色产品主图

同一印花对应多种实际可售产品颜色时，主配色的场景主图组合展示各色产品，突出颜色丰富且每个产品都清楚展示**同一款印花**；其他颜色子体的主图使用该颜色的单产品及对应印花。只有一种可售颜色时使用单产品场景主图。多色组合按产品形态、数量和场景灵活排布，保持每个颜色、产品及印花可辨认；不把不同印花混入同一款主图，不自行添加未售颜色、颜色角标或额外文字，也不暗示组合为多件装。按目标平台的主图及变体规则核实组合是否适用；若平台有冲突，按其要求制作相应版本并说明。

若用户明确提供不同颜色对应不同印花，按实际对应表规划各款图和变体，不擅自替换或统一印花；单张多色图若需不同印花源，须另行制定并验证模板方案，不能声称单源工具自动完成。多色场景主图仍须符合上述真实场景、产品清晰和整套场景差异要求。

尺寸只标有依据的维度及用户/平台需要的单位，换算须准确。根据产品形态、构图、留白、复杂程度自由调整文字与排版；保持产品和印花清晰、手机可读、英文与参数正确。图片生成工具完成场景、图片文字、尺寸标注及正式排版；Photoshop 用于印花母版、真实可印区域、遮挡、变形和必要光影，不以 PS 补字替代修正生成画面。

按用户需要准备标题、卖点和描述；共享内容只引用该系列通用、可证实的事实，随印花变化的内容明确区分。核实平台当前要求，不把示例字数视为官方限制。资料不足时交付有依据部分，标明缺项。

## 首套、PSD 与批量

1. 先做完整首套：生成固定场景和已定稿图文，印花区域不留旧图案；再按真实可印面制作 PSD，导出带图案的完整预览。检查每张都有适合产品的复合型场景、整套至少三个不同场景（按实际交付范围适用）、构图与色调差异、产品一致性、可读性、事实、印花位置、完整边界及遮挡；重复场景或只换背景色、文字的画面应重新规划。用户要求连续执行时自行检查并记录委托，不能冒称用户已审核。
2. 新建联动模板及换图时读 [共享母版流程](references/shared-mockup.md) 与 [配置](assets/workbench-profile.json)。每个模板族使用共享母稿、按实际范围声明场景数和每图实例数；无印花共用图为 0，所有可见印花实例都须纳入替换。多色主图逐个记录颜色、印花区域、比例、透视、遮挡及实例，换款后核验各颜色产品同步为对应印花，不只检查第一个实例。不同尺寸或结构按实际映射决定模板族。
3. 使用 Inspect → manifest → plan → Export → 交付检查；母稿的实际像素和 PPI 为准，manifest 必须显式记录并核对实际 PPI，不依赖工具对缺值的 72 PPI 回退；依据设计选择 canvas/cover、canvas/contain 或 alpha/contain。批准后冻结模板和哈希，换图时保持场景、文案、映射与保护区域；修订另存版本。
4. 现有运行工具每个 PSD 只处理一个共享印花源；正反面不同图案或独立通道需要独立模板/映射方案，不能声称单源自动支持。Build 仅辅助平面四角及多边形，曲面、褶皱、孔洞、五金和遮挡须按实物制作并验证；脚本通过不代表任意产品视觉或曲面通过。
5. 对实际模板测试代表性的满版、透明、比例与边界，检查重要内容裁切、所有实例、保护区域、产品融合和原模板哈希。导出报告、完整套数和视觉验收分别记录；失败保留原因与已完成产物，不标记成功。

按用户范围交付成图、可编辑母版、印花、文案及总览；未要求打包时不额外打包。单纯换图或制作总览时复用已批准成果，不重新生成场景。工具、文件和运行报告的验证范围不能代替真实商品、平台或视觉验收。

运行联动 PSD 需要可用的桌面 Photoshop、PowerShell 和 Python；交付图像检查器还需要 Pillow。先检查依赖，缺失时记录并说明受影响的验证，不将文件检查或技术小样冒充真实 PSD 验收。自动运行与人工操作遵循 [共享母版流程](references/shared-mockup.md) 的互斥、失败和取消约定。
