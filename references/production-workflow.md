# 先定稿母版，再快速换印花

## 两个阶段不可倒置

**设计阶段**完成第一款完整轮播图：产品事实、买家与购买理由、场景和构图、卖点证据、情绪文案、正式原生排版、印花融合、可复用PSD。先修好这套图，再扩大图案数量。3–5种样式不再作为“完整视觉之前必须先暂停”的流程主线；如技术可行性确实未知，可做最小单角度探测，但它不等于母版定稿。

**生产阶段**复用已批准或明确委托完成的母版。记录版本与SHA256，仅替换印花智能对象及工具支持的主题字段，导出每款完整套图。禁止每种印花重做PSD、逐张调用生成模型重绘产品或改场景。

## 责任与不变量

| 项目 | 执行要求 |
|---|---|
| 实物身份 | AI根据实物与用户确认制作；供应商印刷展示不等于结构纹理 |
| 来源一致 | 无印花底图→同一PSD→带印花图；不先做成品再擦图重建 |
| 模板创建 | AI主动建立区域蒙版、必要透视、前景与光影，正式文字可编辑 |
| 固定替换 | 固定工具操作声明的内容；不修改冻结模板、蒙版、前景或变形 |
| 图案来源 | 指定图案按指定ID使用；有授权的独立原稿或一次性修复图；随机仅按明确需求并记录种子 |
| 透明／满覆盖 | 透明处露出原底色；满覆盖由蒙版限制，不覆盖五金、镜面、手指等 |
| 主题文案 | 共用文案，或独立文字字段且工具真实支持；不得残留首款主题 |
| 完整套数 | 每种印花都是完整七图；共用源图可以重复加入各套目录，不额外增加图位 |
| 停止修改 | 用户确认“不再改”后仅执行输出类动作；修改需求另开版本 |

有手持场景时检查真实手指是否进入印花面：进入就建立前景层／遮挡蒙版；如果手只在外框或底部，记录无交叉的判断并以满覆盖验证。不要无意义地添加前景层，也不能以缩小图案躲开遮挡测试。

## 审核与冻结

默认提供资料、方案、第一套最终七图等有价值的确认节点；用户已批准的同版本信息不重复询问。用户明确“中间不暂停”优先，记录 `first_set_review.status=delegated`、原话依据和 `ai_visual_review=true`；这不是 `approved`。普通批准记录 `approved` 和对应成品版本。

第一套自查与审核包括购买逻辑、场景差异、构图、正式文字、可读性、卖点、尺度及产品一致性。冻结前可改同一套母版；冻结后记录哈希，所有后续换图保持它不变。用户后续只索要四宫格或打包，不使批准失效。

## 声明范围内的验收

1. 重开保存后的真实PSD，检查智能对象类型、区域蒙版、前景、透视和文字层，不能只看图层名字。
2. 用实际销售图案测试；按适用范围覆盖纯文字、图文、透明底与全区域压力图，再测横／竖／近方比例。缺样式只标技术测试，不擅自新增销售款。
3. 比较印花区域之外的像素；检查边框、五金、镜面、手指和主题文字，原透明处没有旧图／白方块。
4. 同一模板与图案重复导出应一致；固定PSD SHA256前后不变。记录工具入口／哈希、规格、源画布和日志。
5. 整套视觉检查与有限工具检查分开。只有上述真实证据通过才称 `verified_for_declared_templates`；这个状态不证明任意曲面、其他产品或平台政策。

矩形环境小样通过仅证明COM与基本保存替换。`photoshop.ps1 Build` 不会创建商品蒙版／透视；`TrialReplace` 可保留母版已有结构。经过真实商品验证的特定模板应明确报告可用，不必等一个无关的通用图库／独立批处理系统。但未测试的能力不能宣称支持，失败项标 `tool_validation_pending` 并具体描述。

## 进度与效率

首次母版制作含场景生成、排版和修正，耗时与冻结后的换图不同；不要把两者混称“套图慢”。记录影像调用次数、模板创建次数、替换次数和交付动作；已有素材则不重新清晰化，环境未变则复用检查，预览及压缩包未变则复用。底图是中间产物，正式成品预览优先。实际交付工具见 [delivery.md](delivery.md)。
